## المسار 0 — كيف تشتغل خوارزمية ميتا (الأساس)

> ⏳ **قيد البحث المعمّق الآن** (deep-research harness). النتائج المُتحقق منها بمصادرها تُدمج هنا فور اكتمالها. هذا المسار أولاً لأن كل قرار تصميمي في المكوّنات الستة يعتمد على فهم الآلة.

محاور الغوص:
1. **المزاد:** القيمة الكلية = عرض السعر × معدل الفعل المتوقّع × جودة الإعلان — كيف يُحسب كل عامل، ومن يفوز.
2. **التسليم والـ pacing:** كيف توزّع ميتا الميزانية على اليوم، وكيف تقرّر لمن تعرض.
3. **مرحلة التعلم:** آلية الـ ~50 حدثاً/أسبوع، ما الذي يصفّر التعلم بالضبط، وحالة Learning Limited.
4. **CBO/Advantage:** توزيع الميزانية اللحظي بين المجموعات، ولماذا التوحيد يساعد.
5. **الإشارات وEMQ:** كيف يدرّب البكسل/CAPI الخوارزمية، درجة مطابقة الحدث، ونوافذ الإسناد.
6. **الـ Lookalike:** كيف تُبنى، وأثر جودة/حجم المصدر، وكيف تشكّلها إشارات الشراء.
7. **تداخل المزادات:** كيف تنافس نفسك، وتكلفة تشتت الجمهور.
8. **خصوصية CTWA:** كيف تُحسّن إعلانات المحادثة، وتدفّق ctwa_clid، ودور نافذة الرسائل.
9. **الكرييتف والإرهاق:** كيف تُقيّم الخوارزمية الكرييتف، والتنوّع، والـ frequency/fatigue.

## المكوّنات الستة (كل بند = مسار بحث مستقل ثم بناء)

### المكوّن 1 — الكتالوج وProduct Sets · حالة: مبني جزئياً · أولوية: MVP
- **الفجوة:** لا Product Sets (نساء>بلايز/قمصان)، ورفع الـ feed يدوي، ولا مزامنة توفر تلقائية (نفاد ← إيقاف إعلاناته).
- **أسئلة البحث:** حدود الكتالوج والـ sets؛ scheduled feeds مقابل رفع يدوي مقابل API؛ قواعد فلاتر الـ set برمجياً؛ ربط نفاد المخزون بإيقاف الإعلان.
- **مصادر:** developers.facebook.com/docs/marketing-api/catalog · Commerce Manager help · product-sets API.

### المكوّن 2 — توليد الإعلانات بالجملة · حالة: مبني جزئياً · أولوية: MVP
- **الفجوة:** محور واحد (موديل×لون) بلا Product Set targeting؛ لا حملة إعادة استهداف؛ لا انتقال لهدف Purchase؛ مسار الـ SDK غير مُختبَر حياً.
- **أسئلة البحث:** هيكل حملة هدف المراسلة عبر Marketing API بالضبط؛ إعداد CTWA برمجياً (promoted_object، destination_type)؛ Advantage+ Audience مقابل Lookalike يدوي؛ سقوف adset؛ متى/كيف الانتقال لـ Purchase objective.
- **مصادر:** Marketing API campaign/adset/ad ref · CTWA setup docs · Advantage+ audience docs.

### المكوّن 3 — القياس CAPI/ctwa_clid · حالة: مبني · أولوية: MVP (صقل)
- **الفجوة:** لا حدث تصحيح استلام COD؛ لا قياس EMQ؛ لا تأكد من نافذة الإسناد.
- **أسئلة البحث:** رفع EMQ لأحداث المراسلة؛ حدث Purchase عند التأكيد + تصحيح عند الاستلام الفعلي؛ نوافذ الإسناد لـ CTWA؛ منع التكرار عبر event_id.
- **مصادر:** Conversions API for business messaging docs · EMQ guide · attribution settings.

### المكوّن 4 — البوت المحادثاتي · حالة: مفقود (الأكبر) · أولوية: MVP حرج
- **التوصية:** **هجين** — قواعد للأسئلة المتكررة (سعر، توفر، مقاسات، عرض 3 قطع) + ذكاء للغامض فقط. اختيار موديل الذكاء بند بحثي (محلي مجاني مقابل API مدفوع).
- **الفجوة:** كل شيء — لا إرسال واتساب، لا intent، لا آلة حالة محادثة، لا MPM.
- **أسئلة البحث:** WhatsApp Cloud API send + الرسائل التفاعلية + Multi-Product Messages؛ ميكانيكا نافذة الـ 24 ساعة (متى مجانية، متى قالب مدفوع)؛ تصميم intent هجين؛ مقارنة موديلات الذكاء (تكلفة/جودة/عربي/لهجة)؛ سياسة يناير 2026 (لا بوتات AI عامة — نطاق بزنس واضح).
- **مصادر:** developers.facebook.com WhatsApp Cloud API · interactive/MPM docs · messaging policy.

### المكوّن 5 — الطلب والاقتصاديات · حالة: مفقود · أولوية: MVP
- **الفجوة:** `order_cli.py` يدوي بديلاً عن آلة حالة؛ لا حساب هامش/ربح؛ لا إدارة RTO/عربون.
- **أسئلة البحث (تنفيذية أكثر من بحثية):** آلة حالة الطلب (جديد←مؤكد←مشحون←مستلم/مرفوض)؛ اقتصاديات الطلبية بأرقام المستخدم (بلوزة 85/كلفة 30، قميص 105/كلفة 40، توصيل فعلي 60/معروض 40/مجاني فوق 250، استلام 80%، كلفة طلبية إعلانية 45-55→35)؛ خفض RTO (تأكيد صريح، عنوان، عربون Bit، ذاكرة سوداء للرافض)؛ ربط نسبة الرفض بالإعلان في `rules.py`.
- **مصادر:** بيانات المستخدم الفعلية + أبحاث COD/RTO الإقليمية المحفوظة.

### المكوّن 6 — البنية والتوسّع · حالة: جزئي (SQLite فقط) · أولوية: توسّع
- **الفجوة:** لا redis (كاش/طابور)، لا تخزين كائني للصور، لا إدارة System User tokens، لا معالجة حدود المعدّل، لا تعدد أرقام.
- **أسئلة البحث:** متى SQLite يكفي ومتى ننتقل لـ Postgres/Mongo؛ Redis للطابور تحت الضغط؛ System User Token (لا ينتهي)؛ حدود معدّل Graph API؛ توسّع تعدد الأرقام تحت WABA واحد.
- **مصادر:** Graph API rate limits · System User docs · بنية النظام المرجعي (Celery/Redis/Mongo مرجّح).

## قابلية التوسّع — مبادئ محفورة من الآن

1. **مفتاح الفئة `product_type`** (نساء>بلايز...) هو محور التوسّع: إضافة أطفال/ساعات لاحقاً = Product Set جديد + فلتر، بلا إعادة بناء.
2. **بنية تحتية واحدة** (BM/Dataset/كتالوج/WABA) تخدم كل الخطوط — قرار محسوم بالدراسة.
3. **الطبقات مفصولة:** قياس/إطلاق/قتل مستقلة عن البوت — كل مكوّن يُبنى ويُختبر ويُطلق وحده.
4. **الأسرار خارج الكود دائماً** (`.env` / System User Token) — درس `credentials.json`.
